# マスターに沿った日英スライド制作

研究発表、成果物・プロジェクトの紹介、授業などで使う、編集可能なPPTXとPDFを作るためのスキルです。読者の疑問から構成を考え、一次資料の確認、組版、描画、照合、納品までを扱います。

## スキルの選び方

|用途|読むファイル|役割|
|---|---|---|
|研究発表・成果物発表・紹介・授業など|[master-guided-slides/SKILL.md](.agents/skills/master-guided-slides/SKILL.md)|共通の情報設計、日英の表現、組版、出典、描画・検証、納品|
|データセットの紹介|[dataset-introduction-slides/SKILL.md](.agents/skills/dataset-introduction-slides/SKILL.md)と上の汎用スキル|課題と実例、収集・注釈、単位・統計、評価、利用動向、入手、読後の資料|

手順を記すファイルは、この2つの`SKILL.md`です。[SlideMaster.pptx](.agents/skills/master-guided-slides/SlideMaster.pptx)は共通のマスターとして1か所に置きます。汎用制作には汎用スキルとマスター、データセット紹介には専門スキルも加えて使います。共通の組版規則を二重管理しません。

## 配置と使い方

```text
.agents/skills/
├── master-guided-slides/
│   ├── SKILL.md
│   └── SlideMaster.pptx
└── dataset-introduction-slides/
    └── SKILL.md
```

利用先プロジェクトの`.agents/skills/`へ、必要なフォルダをこの相対位置でコピーしてください。汎用制作だけなら`master-guided-slides/`、データセット紹介も行うなら両方を配置します。過去の参考スライド、共有Pythonスクリプト、別添設定ファイルは不要です。材料と発表条件を与え、制作・検証用の一時コードは利用環境で作れます。

依頼には、材料、発表の目的、言語、時間、作成者・所属、必要な出力形式を含めます。指定がなければ、聴衆は当該分野の学部4年〜修士1年相当です。著者名・シリーズ名・日付・保存先などは、その依頼に合わせます。

### 研究発表

> $master-guided-slides を使い、添付論文の研究の問い、方法、結果を学会発表のスライドにしてください。日本語、本編15分。作成者・所属は編集可能な欄を残し、完全版のPPTXとPDFを提示してください。

### 成果物発表

> $master-guided-slides を使い、このプロジェクトの課題、使い方、実演、評価を紹介してください。日本語、本編10分。入力と出力の対応が分かる実例を含め、PPTXとPDFを提示してください。

### データセット紹介

> $dataset-introduction-slides を使い、指定したデータセットを紹介してください。日本語、本編10分とAppendix。目的、実例、作成方法、規模と分布、評価、現在の利用、入手方法、読後の学習資料を調べ、完全版のPPTXとPDFを提示してください。

## 共通の制作方針

- 聴衆が知りたいことから構成を作り、追加情報やフィードバックがあれば本編・補足の配分と順序を見直します。
- 無駄な文字列を減らし、主張・結果・例を大きく、照合用の出典・IDを明確に小さくします。本文は自然に折り返し、通常本文のタイトルは一行に収めます。表紙・章扉・転換ページでは意味のまとまりで行を整えます。
- 本編と長いAppendixにはセクション番号付き目次を置き、本編が15枚以上なら章扉を入れます。スライド間のページ参照や制作中のファイルへの案内は載せません。
- ネイティブな箇条書き・番号付きリストを使います。バレットは親子とも約13.3 pt。LibreOfficeにも反映する`buSzPct`とバレットフォントの明示を使い、本文と目次番号は独立して設定します。
- 引用、表、グラフは実際に描画して読みやすさを確認します。引用枠は全行の位置から上下の余白を決め、表や引用の後ろの説明も移動します。
- ページの出典は根拠の照合先、末尾の参考文献は読後の学習・研究への入口にします。後者は正式タイトルを省略せず、著者・年・掲載先を記載します。書誌情報から独立した紹介文で、その資料の特徴・貢献・位置付けを簡潔に述べます。学習効果や行動案内で代用しません。
- 完全版PPTXと、同じ改訂から出力したPDFを個別リンクで納品します。発表者ノートや本編だけの版は、明示的な依頼がある場合に作ります。

具体的な座標、色、文字サイズ、XML構造、確認手順は汎用スキルを参照してください。口頭発表と黙読の時間設計、具体的な定義、モデルの年、丸ラベルの描画上の中央揃えは汎用スキルへ、先行データ・課題・注釈形式・実例の照合はデータセット紹介スキルへ反映しています。今回の全資料の改訂では、ImageNet・SNLI・SQuAD・UCF101・COCOの成果物をすべて再構成しています。

## 編集・描画に必要な環境

PowerPointやLibreOfficeなど、PPTXを編集・描画できる環境を使います。コードで編集する場合は、利用環境に応じて`python-pptx`、`lxml`、PDF確認にはPyMuPDFなどを使えます。特定の配布スクリプトに依存しません。

日本語はNoto Sans CJK JP、英数字はNoto Sans、コードはLiberation Monoなどの等幅フォントを使います。Windows・macOS・Linuxで編集する場合も、同じ配布版・バージョンのフォントを用意してください。フォント名の指定とフォント本体の配布・埋め込みは別であり、各ライセンスに従います。フォント本体はこのリポジトリに同梱していません。代替した場合は、字体と再現上の制約を納品時に明記します。

検証では、全ページの描画、PPTXとPDFの文字照合、マスター・レイアウトとリストの編集構造、内部参照、対象形式のXMLスキーマを確認します。PowerPointでの修復を求められた場合は、修復前後のXMLを比較して原因を調べます。特定のソフトでの開封や未実施のチェックを、検証済みとは扱いません。
