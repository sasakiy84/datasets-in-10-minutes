## データの範囲と集計

開発用は15主課題・50生成段階、テスト用は65主課題・288生成段階。テスト側の固定コード3段階（13.6、62.1、76.3）を加えると、配布JSONLには341段階のレコードがある。論文の338は生成対象の合計と対応する。HFのsplit名は開発用が `validation`、テスト用が `test`。参照解は開発用に公開され、テスト用には含まれない。

各生成対象の `test_cases` 配列の長さを集計すると、開発用167件、テスト用915件、合計1,082件。両集合の中央値は3件。80主課題を生成段階数でまとめると、1段階10件、2–3段階34件、4–5段階19件、6–9段階12件、10段階以上5件。中央値は3段階。

分野別の図と16小分野の表は論文の分類を使った。数学14・物理37・化学8・生物8・材料科学13で80件。公式サイトの問題分類一覧は取得時点で79主課題（61が未掲載）のため、一覧から80件の分類を推定しなかった。READMEには「6 domains」という旧文面もあるが、列挙された分野および論文に合わせて5分野とした。

## 固定段階とInspect AI実装

固定コードは、Maxwell場を扱う13.6、DMRGのブロッククラス62.1、DNA配列生成器76.3。FAQの76.2という記載に対し、評価コードと固定ファイルは76.3を指定しているため後者に合わせた。

参照した `eval/inspect_ai/scicode.py` は、固定段階を生成・採点のループから省く一方、`total_steps = len(sub_steps)` を用い、主課題の正解を `total_correct == total_steps` で判定する。固定段階以外が全通過した場合も、主課題13は14/15、62は5/6、76は3/4となる。この条件式と判定式を当該ソースのASTから取り出して確認し、Appendixに実装上の挙動として掲載した。モデル比較ページで使われた実装は特定していない。
