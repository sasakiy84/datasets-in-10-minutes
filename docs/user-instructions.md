添付ログは番号が1から始まる3群（10件、34件、12件）を含んでいます。群をまたぐ厳密な時系列は元ファイルから確定できないため、保存されていた順で原文を掲載します。ログに同名の添付ファイルへの言及があっても、未提供の本文を補完したとは扱いません。今回確認できた2つの添付ファイルはバイト単位で同一だったため、本文は1回だけ掲載します。

【20】汎用的なフィードバックと情報設計

SNLI についてのフィードバックだけど、他の事例についても同じ。汎用的な部分は他のスライドについても修正して

スライドは引き算なので、スライドの中の余計な記載はできるだけ減らしたい。これは情報量を減らすということではなく、無駄な文字列を減らすということで、たとえば、単語は Python の str.split() による空白区切り。サブワード数ではない。という説明は、前半部分だけでサブワード数ではないということがわかるので、後半はいらない。また、読んで欲しい情報と必要であれば見つけられる程度の情報をきちんと区別して大袈裟に表現する。たとえば、SNLI p. 6 の文対 ID 4460943467.jpg#0r1c （テスト用）は中途半端になっていて、ユーザーはSNLIを理解するためにこのIDを覚える必要はないので、もっと文字を小さくして、[1] の末尾におけばいい。また、スライドでは p. 13 の２つめの箇条書きのように自前で文を改行しなくていい。句点を打って、テキストボックスの範囲で改行するのに任せればいい。参照番号は句点の前において。利用の変遷について、読者が特に知りたいのは出てきた当時の状況やそれぞれのモデルのパフォーマンスと、現役かどうかあたり。このように、ユーザーがどのような情報を知りたいかを検討するという情報設計をしてスライドの並び順や情報の出し方を考えて。新しい情報が追加されたら、また情報設計をやり直して。本編にも目次をつけてほしいし、15枚以上の本編があるときはセクションの変わり目にはタイトルスライドも入れて欲しい。
